# UI Drop-In Procedure

Use when copying screens generated by an external design tool into `apps/web`.

## Steps

1. **Inventory first.** List every component the generated code imports. Compare against existing `src/components/ui/*` (shadcn). Missing primitives: add via `pnpm dlx shadcn@latest add <component>` — never paste vendored shadcn copies from the generator if the CLI can provide them.
2. **Path alignment.** Generated files go to the exact routes/components in docs/ui-spec.md route map. Rewrite import aliases to `@/...`. Delete vendor boilerplate: analytics snippets, `@vercel/*` imports, provider wrappers you didn't ask for, hardcoded metadata duplicates.
3. **Strip logic contamination.** External generators often sneak in API routes, auth calls, DB clients, env reads. Remove all — this app's rule: presentational components take typed props; data comes from `src/lib/mock-data.ts` until wired to Supabase.
4. **Type reconciliation.** Replace generator-invented types with the canonical ones in docs/ui-spec.md (ProgramRow, EvidenceEntry, FiltersState...). Fix compile errors at the component, never by weakening types (`any`, optional-chaining chains).
5. **State completeness.** Verify loading (skeleton), empty, error states exist per docs/ui-spec.md; add missing ones using existing patterns.
6. **Responsive check.** Tables must degrade to stacked cards under `md`. Test 360px width in dev tools.
7. **Hygiene pass.** Run `pnpm lint && pnpm typecheck && pnpm test`; remove unused exports/dead CSS; ensure no inline secrets; dark-mode tokens intact (no raw hex in components except via theme vars).
8. **Update ledger.** Note in docs/tasks.md which task's UI this satisfies; list any deviations in docs/state.md.

## SPA exports (Lovable / Manus.im / similar full-app generators)

These tools emit a Vite-style React SPA. Convert mechanically:

1. Each generated screen file (`src/pages/*.tsx`) → keep as a client component under `src/components/pages/`, then create a thin Next.js route at the matching path from docs/ui-spec.md (`src/app/results/page.tsx`) containing `"use client"; export { default } from "@/components/pages/results";` (or importing the component).
2. Replace `react-router-dom`: `Link` → `next/link`, `useNavigate` → `next/navigation` `useRouter`, route params via page `params` prop instead of `useParams`.
3. Delete generator runtime files: main entry, router config, vite config, service workers, PWA manifests, analytics.
4. Keep `src/lib/types.ts` and `src/lib/mock-data.ts` verbatim — they match our canonical contracts; move to `apps/web/src/lib/`.
5. If dynamic routes were used (`/programs/:id`), wire mock lookup by `id` inside the page component until Supabase data lands.

## Red flags requiring rewrite (not adaptation)

- Business rules embedded in JSX (eligibility calculations, score math → belongs in `src/lib/matching.ts`)
- Direct supabase-js calls inside components (data access goes through lib layer)
- Non-deterministic rendering (Date.now() during render for deadlines → compute in helpers, testable)
